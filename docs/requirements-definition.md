# YouTube コマ送りスクロール拡張 要件定義書

確定版。
仕様に関する各項目の決定内容は `docs/decision-records.md` を参照する。
実装への分解は `docs/implementation-plan.md` に記す。

## 背景と目的

YouTube で一時停止した動画をコマ単位で送りたい、という要求が出発点である。

YouTube 本体にも一時停止中のコマ送りはあり、キーボードの `,`（1 コマ戻り）と `.`（1 コマ送り）で操作できる公式機能である。
ただしこの操作はキーボードに限定されており、マウスだけで完結しない。

本拡張は、一時停止中のプレイヤー上でマウスホイールをスクロールしたときにコマ送りまたはコマ戻しを行う Chrome 拡張である。
併せて、現在のフレーム位置とタイムコードをオーバーレイで可視化し、何コマ移動したかを把握しやすくする。

## 対象範囲

対象は youtube.com の動画視聴ページ（watch ページ）のメインプレイヤーと、YouTube Shorts のプレイヤーである。
全画面表示、シアターモード、ミニプレイヤーでも同一の動画要素を追従する。
対象範囲の選定は仕様決定 D に従う。

次の場面では機能を無効化する。

- 広告の再生中。
  広告映像をコマ送りする需要はなく、広告再生中のシーク操作は挙動を壊す可能性がある
- ライブ配信とプレミア公開のリアルタイム再生。
  コマ送りの意味を持たない

次の対象は範囲外とし、将来の拡張候補とする。

- 外部サイトに埋め込まれたプレイヤー
- Chrome 以外のブラウザ

Shorts ではスクロールが本来ショート動画の送り操作に使われている点に注意が必要である。
一時停止中に限りスクロールをコマ送りへ割り当て、再生中のスクロールは従来どおりフィード遷移に使われる。

## 用語

- **コマ送り**：表示中のフレームを 1 フレーム先へ進める操作。
- **コマ戻し**：表示中のフレームを 1 フレーム前へ戻す操作。
- **フレーム番号**：動画の先頭から数えたフレームの通し番号。
  本拡張では `currentTime` に fps を掛けて丸めた推定値として扱う。
- **fps**：動画のフレームレート。
  実際の値は動画ごとに異なり、非整数（29.97 など）もある。
- **ホイール蓄積**：スクロールイベントの `deltaY` を累積し、閾値を超えるごとに 1 コマとして消費する仕組み。

## 機能要件

各要件の ID は「FR-番号」で管理する。
初期版の機能範囲は仕様決定 F に従う。

### FR-1: スクロールによるコマ送りとコマ戻し

動画が一時停止中かつカーソルがプレイヤー領域上にあるとき、ホイールスクロールを捕捉してコマ送りに変換する。
既定は上スクロールで 1 コマ送り、下スクロールで 1 コマ戻しとし、方向は設定で反転できる（仕様決定 A）。

捕捉したスクロールイベントは `preventDefault` でページスクロールへ流さない。
捕捉は既定では一時停止中に常時行うが、設定で「修飾キー（Alt など）を押している間だけ捕捉する」へ変更できる（仕様決定 C）。

### FR-2: ホイール蓄積による 1 ノッチ 1 コマ

マウスホイールの 1 ノッチはおよそ `deltaY` 100 ピクセル分のイベントとして届く。
一方、トラックパッドや高分解能ホイールでは小さな `deltaY` が連続して届き、操作を止めたあとも慣性イベントが続くことがある。
そこで `deltaY` を累積し、閾値を超えるごとに 1 コマとして消費する方式を取る。
閾値は設定で変更でき、既定値はマウスの 1 ノッチに相当する量とする。

慣性イベントによる意図しない連続送りを抑えるため、一定時間入力がないとき累積値を減衰させ、1 秒あたりのコマ数に上限を設ける。

### FR-3: 修飾キーによる複数コマ移動

Shift キーを押しながらのスクロールは 1 ノッチあたり複数コマ（既定 10 コマ、設定で変更可）を移動する。
ただし、スクロール捕捉の修飾キーとして Shift を選択している場合は、Shift が捕捉条件を兼ねるため本機能は利用できない。

### FR-4: フレーム位置のオーバーレイ表示

コマ送りの操作中のみ、フレーム番号、タイムコード（`HH:MM:SS.mmm`）、推定 fps をプレイヤー内の小さなオーバーレイに表示する。
操作が止まってから数秒でフェードアウトし、常時は表示しない（仕様決定 E）。
オーバーレイは Shadow DOM で実装し、YouTube 側のスタイルと干渉しないようにする。

### FR-5: 再生中のスクロール挙動

再生中はスクロールを捕捉せず、ブラウザ標準の挙動（ページスクロール、Shorts でのフィード遷移など）をそのまま通す（仕様決定 B）。
再生中のスクロールに別機能を割り当てない。

### FR-6: 設定画面

拡張機能のオプションページで次の項目を設定できる。
設定値は `chrome.storage.sync` に保存する。

- 機能の有効と無効
- スクロール方向とコマ送り方向の対応（反転設定）
- スクロール捕捉の条件（常時捕捉か修飾キー併用か、および併用キーの選択）
- ホイール蓄積の閾値
- Shift 併用時のコマ数
- オーバーレイの表示と非表示
- fps の手動指定値（検出に失敗した場合のフォールバック）

機能の有効と無効は、ツールバーの拡張機能アイコンからも切り替えられるようにする。

### FR-7: ページ遷移と表示状態への追従

YouTube は単一ページアプリケーションであり、ページ遷移で動画要素が作り直される。
ナビゲーションイベントを検知して初期化とイベント登録をやり直し、全画面やシアターモードへの切り替わりでもオーバーレイの表示位置を追従させる。
watch ページと Shorts ページでプレイヤーの DOM 構造が異なる点を吸収し、両方で同一の操作系を提供する。

## 非機能要件

- Manifest V3 に準拠する。
- 要求する権限は `storage` と、`https://*.youtube.com/` を対象とするコンテンツスクリプトに限定する。
- 外部への通信、データ収集、解析基盤の組み込みは行わない。
  Chrome Web Store への申請では、この方針をプライバシー情報としてそのまま表明できる。
- ポーリングによる監視ループを持たず、イベント駆動で実装する。
  ホイールイベントのハンドラは軽量に保つ。
- 実装言語は TypeScript、ビルドは esbuild とする。
- 単体テストはホイール蓄積とフレーム番号換算を中核に、fps の表記パース、無効化ゲート、オーバーレイ表示整形の純粋関数を対象にする。
  YouTube 実機での動作は手動確認手順として文書化する。
- 設定画面など拡張機能が提供する UI は日本語と英語に対応する。
- 配布はローカル読み込み（開発者モード）、GitHub Release の zip、Chrome Web Store 公開の 3 経路とする（仕様決定 G）。
  ストア公開に必要なアイコン、スクリーンショット、説明文（日本語と英語）を用意する。

## コマ送りの実現方式

HTML の動画要素には「1 フレーム進める」API がないため、`currentTime` への代入によるシークで実現する。
ブラウザはシーク先時刻を含むフレームを表示するため、フレーム周期の刻みで `currentTime` を動かせば、固定フレームレートの動画では実用上フレーム単位の移動になる。

シーク先の時刻は「目標フレーム番号 + 0.5」を fps で割った値とする。
境界ちょうどを指定すると丸め誤差で前のフレームに留まることがあるため、フレームの中央を狙う方式である。
フレーム番号は内部で整数として管理し、スクロールのたびに目標番号を更新してから時刻へ換算する。

連続したスクロールでは `currentTime` への代入が重なってシークを詰まらせる可能性がある。
目標番号の更新は即時に行い、実際のシークは一定間隔（数 10 ミリ秒）にまとめて最新の目標だけを適用する。

この方式には次の限界がある。

- 可変フレームレートの動画では、フレーム間隔が均一でないため等間隔刻みの近似になる。
  YouTube 上の投稿動画はほぼ固定フレームレートと推測するが、ずれが生じた場合に備えてオーバーレイのフレーム番号は「推定値」として扱う。
- `currentTime` シークはフレーム精度を保証する API ではない。
  YouTube のプレイヤー内部関数を呼ぶ代替方式もあるが、非公開 API で仕様変更に弱いため採用しない。

## fps の検出

fps は次の 3 段の優先順位で取得する。

1. 「統計情報」（Stats for nerds）の解像度表記から読み取る。
   実装は `1920x1080@30` のような想定形式に表記揺れを許容したパースで行ったが、DOM 構造への依存が強く、実在の表記形式での検証は未完である。
   未検証の残存分は `docs/manual-test.md`「既知の制約」で管理する。
2. `getVideoPlaybackQuality().totalVideoFrames` と `currentTime` の差分から実測する。
   再生中の一定区間でしか測れないため、一時停止のみの利用では使えない場面がある。
3. いずれも得られない場合は設定画面の手動指定値を使う。
   未指定なら既定値 30 にフォールバックする。

プレイヤーの応答オブジェクト（`getPlayerResponse()`）のフォーマット情報も fps 取得の候補だったが、実装では統計情報、実測、手動値の 3 段で要件を満たすため採用していない。

## 既知の制約とリスク

- 一時停止中はプレイヤー上のスクロールがコマ送りに割り当てられ、同じ位置でのページスクロールは効かなくなる。
  Shorts ではスクロールがフィード遷移を兼ねるため、一時停止中にフィードへ戻る操作はプレイヤー外のスクロールか再生再開で行うことになる。
  修飾キー併用設定で捕捉条件を絞る回避策も用意する。
- 「統計情報」の DOM やプレイヤーの内部構造は YouTube の更新で変わりうる。
  検出に失敗した場合は手動 fps にフォールバックし、エラーを出さず機能だけを狭める。
- 広告の検出はプレイヤーコンテナのクラス名（`ad-showing`、`ad-interrupting`）に依存する方式を採用した。
  クラス判定の単体テストは済んでいるが、実広告での無効化は実環境での検証が未完であり、MT-20 として `docs/manual-test.md`「既知の制約」で管理する。
